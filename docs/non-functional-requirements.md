## 1. 性能

| 項目 | 目標 |
|---|---|
| 表示 | アプリを開いてから2秒以内にボードが表示される |
| 操作 | 追加・編集・移動・並べ替え・削除の結果が1秒以内に画面に反映される |
| 条件 | 上限いっぱい（リスト10個 × カード100枚 = 1,000枚）の状態でも、上の目標を守る |

## 2. 信頼性

| 項目 | 内容 |
|---|---|
| 保存のタイミング | 操作のたびにDBに保存する（保存ボタンはない） |
| まとめて保存 | カードの移動・プルダウンでの並べ替え・一括削除のように、複数のデータを同時に変える操作は、全部成功するか、全部取り消すかのどちらかにする（トランザクション） |
| バックアップ | 起動用のスクリプト（`start.sh`）を実行するたびに、サーバーを起動する前に、DBの中身を `pg_dump`（PostgreSQL のデータを書き出す道具）で `backup` フォルダにファイルとして自動で書き出す |
| バックアップのファイル名 | 書き出した日時を入れる（例：`backup_2026-11-03_093000.sql`） |
| バックアップの数 | 最新の3つを残し、それより古いものは自動で削除する |
| 復元の方法 | `backup` フォルダのファイルを、`psql`（PostgreSQL に命令を送る道具）でDBに読み込んで戻す（手作業） |

## 3. セキュリティ

| 項目 | 内容 |
|---|---|
| アクセスの制限 | 画面（Vite）・サーバー（Spring Boot）・DB（PostgreSQL）のすべてが、自分のパソコンからのアクセスだけを受け付ける（同じWi-Fiにつながった他のパソコンからは開けない）。ログインがないため、これで自分のデータを守る |
| 入力内容の扱い | タイトルなどにプログラムのような文字を入れても、文字としてそのまま表示し、プログラムとして動かない（React は、文字を画面に出すときに自動でこのように扱う） |
| DBへの命令 | 入力内容をDBへの命令（SQL）に直接つなげず、安全な書き方（プレースホルダー）を使う（Spring Data JPA は自動でこの書き方を使う） |
| Git | `backup` フォルダは、Git の管理に含めない（データをうっかり公開しないため）。DBのデータは Docker の中に保存されるため、プロジェクトのフォルダには入らない |

## 4. 使いやすさ

| 項目 | 内容 |
|---|---|
| 言語 | 画面の文字はすべて日本語 |
| キーボード | 入力欄では Enter キーで確定、Esc キーで取り消し |
| 色への配慮 | 期限切れは色だけでなく「期限切れ」の文字でも表示する。ラベルは色にマウスを乗せると名前を表示する。優先度は色だけでなく矢印と文字（↑ 高・→ 中・↓ 低）でも表示する |
| 色の混ざりを防ぐ | ラベル（カテゴリ）と優先度は置き場所と形を分ける（ラベルはカードの上の端の帯、優先度は右上の文字入りのバッジ） |
| ドラッグ中 | まわりのカードをなめらかにずらして、カードが入る場所を空ける。入る場所には、ドラッグ中のカードを薄く表示する。別のリストへ持っていったときも、そのリストのカードがずれる。マウスには、少し傾けたカードがついてくる |

## 5. 保守性

| 項目 | 内容 |
|---|---|
| 使う技術・ライブラリ | [技術スタック](tech-stack.md) を参照 |
| 有料の部品・サービス | 使わない。必要になった場合は、事前に相談して決める |
| コメント | 主な処理には日本語で説明を書く |
| 管理 | プログラムは Git で管理する |
