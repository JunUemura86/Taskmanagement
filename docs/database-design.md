## 1. 共通のルール

**型**

PostgreSQL で使う型は次のとおり。

| 型 | 入れるもの | 例 |
|---|---|---|
| BIGINT | 大きな整数（ID に使う） | `1` |
| INTEGER | 整数 | `0` |
| VARCHAR(n) | n文字までの文字 | `買い物` |
| BOOLEAN | はい／いいえ（true / false） | `false` |
| DATE | 日付 | `2026-11-10` |
| TIMESTAMPTZ | 日時（時差の情報つき） | `2026-11-02 00:30:00+00` |

**その他のルール**

| 項目 | ルール |
|---|---|
| ID | `GENERATED ALWAYS AS IDENTITY` で自動で採番する。一度使った番号は、削除後も再利用しない |
| 作成日時・更新日時 | TIMESTAMPTZ 型で保存する。DBの中では世界標準時（UTC）で保存され、取り出すときに日本時間などに直せる |
| 更新日時の更新 | 内容や並び順を変更したときに、プログラムで現在の日時に更新する（いつ更新するかは、各表の updated_at の説明を参照）。ラベル表は画面から変えないので更新しない |
| 入力のチェック | 文字数や優先度などのルールは、画面・サーバー・DBの3か所でチェックする。DBでは CHECK 制約（決まった値以外を入れられないようにするしくみ）を使う |
| 件数の上限 | リスト10個・1つのリストのカード100枚の上限は、プログラムでチェックする（DBではチェックしない） |
| 外部キー | PostgreSQL は最初から外部キーのチェックが有効なので、特別な設定はいらない |
| テーブルの作り方 | テーブルを作る SQL は Flyway のファイル（`V1__create_tables.sql` など）に書き、サーバーの起動時に自動で実行する |

## 2. リスト表（lists）

| 項目名 | 日本語名 | 型 | 必須 | 初期値 | 制約・説明 |
|---|---|---|---|---|---|
| id | ID | BIGINT | ○ | 自動で採番 | 主キー |
| name | リスト名 | VARCHAR(30) | ○ | | 1〜30文字 |
| position | 並び順 | INTEGER | ○ | | 左から 0, 1, 2… |
| is_done | 完了用かどうか | BOOLEAN | ○ | false | true にできるのは1つのリストだけ（下の「1つだけのしくみ」を参照） |
| created_at | 作成日時 | TIMESTAMPTZ | ○ | 現在の日時 | |
| updated_at | 更新日時 | TIMESTAMPTZ | ○ | 現在の日時 | 名前の変更、完了用の指定・解除、並べ替えで position が変わったときに更新する（指定・並び順が変わらないときは更新しない） |

**完了用リストを1つだけにするしくみ**

- 「is_done が true の行」だけを対象にした**部分ユニークインデックス**を作る。これで、完了用リストが2つ以上できないことを DB でもチェックできる
- SQL の例：`CREATE UNIQUE INDEX lists_only_one_done ON lists (is_done) WHERE is_done;`

## 3. カード表（cards）

| 項目名 | 日本語名 | 型 | 必須 | 初期値 | 制約・説明 |
|---|---|---|---|---|---|
| id | ID | BIGINT | ○ | 自動で採番 | 主キー |
| list_id | リストID | BIGINT | ○ | | 外部キー（lists の id）。リストが削除されたら、カードも一緒に削除する（`ON DELETE CASCADE`） |
| label_id | ラベルID | BIGINT | | なし | 外部キー（labels の id）。ラベルなしの場合は空（NULL） |
| title | タイトル | VARCHAR(100) | ○ | | 1〜100文字 |
| priority | 優先度 | INTEGER | ○ | 2 | 1（高）・2（中）・3（低）のみ |
| due_date | 期限 | DATE | | なし | 期限なしの場合は空（NULL） |
| position | 並び順 | INTEGER | ○ | | リストの中で上から 0, 1, 2… |
| created_at | 作成日時 | TIMESTAMPTZ | ○ | 現在の日時 | |
| updated_at | 更新日時 | TIMESTAMPTZ | ○ | 現在の日時 | 編集画面で保存したとき、所属リストか position が変わったとき（ドラッグでの移動・並べ替え、プルダウンでの並べ替え、ほかのカードの移動で並び順が振り直されたとき）に更新する。所属リストも position も変わらないカードは更新しない |

- プルダウンで並べ替えたときは、そのリストの全カードの position を新しい順番で更新する。何枚ものカードを同時に変えるため、全部成功するか全部取り消すかのどちらかにする（トランザクション。[非機能要件](non-functional-requirements.md) の「2. 信頼性」を参照）
- 並べ替えで position が変わったカードは、updated_at も更新する。position が変わらなかったカードは更新しない

## 4. ラベル表（labels）

| 項目名 | 日本語名 | 型 | 必須 | 初期値 | 制約・説明 |
|---|---|---|---|---|---|
| id | ID | BIGINT | ○ | 自動で採番 | 主キー |
| name | 色の名前 | VARCHAR(10) | ○ | | 同じ名前は登録できない（UNIQUE）。画面では、色にマウスを乗せたときに表示する |
| color_code | 色コード | VARCHAR(7) | ○ | | `#RRGGBB` の形（例：`#E5484D`） |
| position | 並び順 | INTEGER | ○ | | 編集画面で左から 0, 1, 2… |
| created_at | 作成日時 | TIMESTAMPTZ | ○ | 現在の日時 | |
| updated_at | 更新日時 | TIMESTAMPTZ | ○ | 現在の日時 | |

## 5. ラベル表の最初のデータ

テーブルを作るときに、Flyway のファイルで次の5件を登録する。ラベルは画面から追加・変更・削除しない。

| id | name | color_code | position |
|---|---|---|---|
| 1 | 赤 | `#E5484D` | 0 |
| 2 | 黄 | `#F5C400` | 1 |
| 3 | 緑 | `#30A46C` | 2 |
| 4 | 青 | `#0090FF` | 3 |
| 5 | 紫 | `#8E4EC6` | 4 |

## 6. DBでのチェック（制約）の一覧

| 表 | 項目 | チェックの内容 |
|---|---|---|
| lists | name | 1〜30文字（空の文字は入れられない） |
| lists | is_done | true は1行だけ（部分ユニークインデックス） |
| cards | title | 1〜100文字（空の文字は入れられない） |
| cards | priority | 1・2・3 のどれか |
| labels | name | 同じ名前は入れられない |
| labels | color_code | `#` と 0〜9・A〜F の6文字（`#RRGGBB` の形） |
