## 1. 共通のルール

| 項目 | ルール |
|---|---|
| URL の始まり | `http://localhost:8080/api` |
| やり取りする形 | JSON（文字コードは UTF-8） |
| 項目名 | キャメルケース（例：`dueDate`、`colorCode`） |
| 日付 | `YYYY-MM-DD` の形（例：`2026-11-10`）。ないときは `null` |
| 並び順 | リスト・カード・ラベルとも、`position` の小さい順に返す |
| CORS（画面からの呼び出しの許可） | 画面の `http://localhost:5173` と `http://127.0.0.1:5173` からの呼び出しだけを許可する。メソッドは GET・POST・PUT・PATCH・DELETE。ほかの場所からの呼び出しは 403 Forbidden になる（設定：`backend/src/main/java/com/example/taskmanagement/config/WebConfig.java`） |

## 3. API の詳細

### A-01 ボードの取得 `GET /api/board`

**返す内容（200 OK）**

```json
[
  {
    "id": 1,
    "name": "未着手",
    "position": 0,
    "isDone": false,
    "cards": [
      {
        "id": 1,
        "listId": 1,
        "labelId": 1,
        "title": "買い物に行く",
        "priority": 1,
        "dueDate": "2026-11-10",
        "position": 0
      }
    ]
  }
]
```

| 項目 | 内容 |
|---|---|
| `id` / `name` / `position` | リストの ID・名前・並び順 |
| `isDone` | 完了用リストなら `true` |
| `cards` | そのリストのカード。カードがないときは空（`[]`） |

### A-02 カードの取得 `GET /api/cards/{id}`

**返す内容（200 OK）**

```json
{
  "id": 1,
  "listId": 1,
  "labelId": 1,
  "title": "買い物に行く",
  "priority": 1,
  "dueDate": "2026-11-10",
  "position": 0
}
```

| 項目 | 内容 |
|---|---|
| `labelId` | ラベルなしのときは `null` |
| `priority` | 1（高）・2（中）・3（低） |

**エラー**

| 状態 | ステータス |
|---|---|
| その ID のカードがない | 404 Not Found |

### A-03 ラベルの取得 `GET /api/labels`

**返す内容（200 OK）**

```json
[
  { "id": 1, "name": "赤", "colorCode": "#E5484D", "position": 0 }
]
```

### A-04 カードの追加 `POST /api/cards`

**送る内容**

```json
{ "listId": 1, "title": "買い物に行く" }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `listId` | 必須 | カードを入れるリストの ID |
| `title` | 必須 | 1〜100文字。改行は入れられない。前後の空白は取り除いて保存する |

- 登録時はタイトルだけを送る（UC-02）。優先度は 2（中）、期限・ラベルは `null` で保存する
- リストの一番下に追加する（`position` は、そのリストで一番大きい値＋1。カードがなければ 0）

**返す内容（201 Created）**：作ったカード（A-02 と同じ形）

```json
{
  "id": 7,
  "listId": 1,
  "labelId": null,
  "title": "買い物に行く",
  "priority": 2,
  "dueDate": null,
  "position": 3
}
```

**エラー**

| 状態 | ステータス | 画面のメッセージ |
|---|---|---|
| タイトルが空・101文字以上・改行入り、`listId` がない | 400 Bad Request | M-08（空のときは画面で先に止めて、入力欄の下に M-05 を出す。サーバーには送らない） |
| その ID のリストがない | 404 Not Found | M-08 |
| リストにカードがすでに100枚ある | 409 Conflict | M-07 |

### A-05 リストの追加 `POST /api/lists`

**送る内容**

```json
{ "name": "確認待ち" }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `name` | 必須 | 1〜30文字。改行は入れられない。前後の空白は取り除いて保存する。同じ名前のリストも作れる |

- 一番右に追加する（`position` は、一番大きい値＋1。リストがなければ 0）
- 完了用リストにはしない（`isDone` は `false`）

**返す内容（201 Created）**：作ったリスト（A-01 のリスト1つと同じ形。`cards` は空）

```json
{
  "id": 4,
  "name": "確認待ち",
  "position": 3,
  "isDone": false,
  "cards": []
}
```

**エラー**

| 状態 | ステータス | 画面のメッセージ |
|---|---|---|
| リスト名が空・31文字以上・改行入り | 400 Bad Request | M-08（空のときは画面で先に止めて、入力欄の下に M-04 を出す。サーバーには送らない） |
| リストがすでに10個ある | 409 Conflict | M-06 |

### A-06 カードの変更 `PUT /api/cards/{id}`

**送る内容**

```json
{ "title": "資料作成", "priority": 1, "dueDate": "2026-11-20", "labelId": 3 }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `title` | 必須 | 1〜100文字。改行は入れられない。前後の空白は取り除いて保存する |
| `priority` | 必須 | 1（高）・2（中）・3（低） |
| `dueDate` | 任意 | `YYYY-MM-DD` の形。期限なしは `null`。過去の日付も入れられる |
| `labelId` | 任意 | ラベルの ID。ラベルなしは `null` |

- 4つの項目を毎回すべて送る（送らなかった項目は `null` として扱う）
- リストと並び順は変えない

**返す内容（200 OK）**：変更したあとのカード（A-02 と同じ形）

**エラー**

| 状態 | ステータス | 画面のメッセージ |
|---|---|---|
| タイトルが空・101文字以上・改行入り、優先度が 1〜3 以外、ないラベルの ID | 400 Bad Request | M-08（空のときは画面で先に止めて、入力欄の下に M-05 を出す。サーバーには送らない） |
| その ID のカードがない | 404 Not Found | M-08 |

- エラーのときは、編集画面を開いたままにし、入力した内容も残す

### A-07 カードの削除 `DELETE /api/cards/{id}`

- 送る内容はない
- 削除したあとも、同じリストのほかのカードの `position` は詰めない（並び順は変わらないため）

**返す内容（204 No Content）**：中身はない

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| その ID のカードがない | 404 Not Found | もう消えているので、画面からも消す |

### A-08 カードの移動 `PATCH /api/cards/{id}/position`

ドラッグ＆ドロップで、カードを別のリストへ動かす（F-07）、同じリストの中で順番を変える（F-08）ときに使う。

**送る内容**

```json
{ "listId": 2, "index": 0 }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `listId` | 必須 | 動かした先のリストの ID。同じリストなら並べ替えになる |
| `index` | 必須 | 動かした先のリストで、上から何番目に入れるか（0 から数える）。**動かすカード自身を除いて数える**。リストの枚数より大きいときは一番下に入れる |

- 動かす前のリストと動かした先のリストの `position` は、上から 0, 1, 2… と振り直す（すき間や重なりが出ないようにするため）
- 例：リストに A・B・C があり、A を一番下へ動かすときは `index` を 2 にする（A を除くと B・C の2枚なので、その後ろ）

**返す内容（204 No Content）**：中身はない（画面はすでに並べ替えて表示しているため）

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| `listId` がない、`index` がない・マイナス | 400 Bad Request | 元の並びに戻して M-08 |
| その ID のカード・リストがない | 404 Not Found | 元の並びに戻して M-08 |
| 別のリストへ動かすとき、そのリストに100枚ある | 409 Conflict | 元の並びに戻して M-07（画面でも先に止める） |

### A-09 リスト名の変更 `PATCH /api/lists/{id}`

**送る内容**

```json
{ "name": "確認待ち" }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `name` | 必須 | 1〜30文字。改行は入れられない。前後の空白は取り除いて保存する。同じ名前のリストも作れる |

**返す内容（200 OK）**：変更したあとのリスト（カードは含まない）

```json
{ "id": 4, "name": "確認待ち", "position": 3, "isDone": false }
```

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| リスト名が空・31文字以上・改行入り | 400 Bad Request | 元の名前に戻して M-08（空のときは画面で先に止め、サーバーには送らずに元の名前に戻す。メッセージは出さない。UC-08） |
| その ID のリストがない | 404 Not Found | 元の名前に戻して M-08 |

### A-10 リストの削除 `DELETE /api/lists/{id}`

- 送る内容はない
- 中のカードも一緒に削除する（DB の設定 `ON DELETE CASCADE` で消える）
- ほかのリストの `position` は詰めない（並び順は変わらないため）

**返す内容（204 No Content）**：中身はない

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| その ID のリストがない | 404 Not Found | もう消えているので、画面からも消す |

### A-11 カードのまとめて削除 `POST /api/cards/bulk-delete`

チェックボックスで選んだカード（複数のリストにまたがってもよい）を、まとめて削除する。
削除する ID の一覧を本文で送るため、DELETE ではなく POST にしている（DELETE に本文を付けるのは避けるのが一般的なため）。

**送る内容**

```json
{ "cardIds": [1, 2, 3] }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `cardIds` | 必須 | 削除するカードの ID の一覧。1件以上・1000件まで（リスト10個 × 100枚） |

- もう消えているカードの ID は無視する（消したい状態にはなっているため）
- 1回の命令（SQL）でまとめて削除する

**返す内容（204 No Content）**：中身はない

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| `cardIds` がない・空・1001件以上 | 400 Bad Request | M-08（1枚も選んでいないときは、画面でボタンを押せなくしている） |

### A-12 完了用リストの指定 `PATCH /api/lists/{id}/done`

**送る内容**

```json
{ "isDone": true }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `isDone` | 必須 | `true` なら完了用リストにする、`false` なら解除する |

- `true` のときは、それまで完了用だったリストの指定を外す（完了用リストは1つだけ。DB の部分ユニークインデックスでもチェックしている）
  - 古い方の解除を先に DB に書き込んでから、新しい方を指定する（順番が逆だと、一瞬だけ完了用が2つになり、DB に断られるため）
- `false` のときは、完了用リストがない状態になる
- すでにその状態なら、何も変えない

**返す内容（204 No Content）**：中身はない（画面はすでに表示を変えているため）

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| `isDone` がない | 400 Bad Request | 元に戻して M-08 |
| その ID のリストがない | 404 Not Found | 元に戻して M-08 |

### A-13 カードの並べ替え `PUT /api/lists/{id}/card-order`

並べ替えのプルダウン（F-17）で条件を選んだときに使う。並べ替えの計算（機能要件「2.6 並べ替えのルール」）は画面で行い、サーバーは送られてきた順番で保存するだけにする（ルールを1か所にまとめるため）。

**送る内容**

```json
{ "cardIds": [3, 1, 2] }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `cardIds` | 必須 | 並べ替えたあとのカードの ID を、上から順に並べたもの。そのリストのカードを、ちょうど全部・1回ずつ含める（100件まで） |

- その順番で `position` を 0, 1, 2… と振り直す
- 全部のカードを1つの処理（トランザクション）で書き換えるので、全部成功するか、全部取り消すかのどちらかになる（非機能要件「まとめて保存」）

**返す内容（204 No Content）**：中身はない（画面はすでに並べ替えて表示しているため）

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| `cardIds` がない・101件以上 | 400 Bad Request | 元の並びに戻して M-08 |
| その ID のリストがない | 404 Not Found | 元の並びに戻して M-08 |
| `cardIds` がそのリストのカードとちょうど同じでない（足りない・多い・同じ ID が2回・ほかのリストのカード） | 409 Conflict | 元の並びに戻して M-08 |

### A-14 リストの並べ替え `PUT /api/lists/order`

リストの見出しのつまみ（⠿）をドラッグして、離したとき（F-18）に使う。形は A-13（カードの並べ替え）と同じにする。

**送る内容**

```json
{ "listIds": [3, 1, 2] }
```

| 項目 | 必須 | ルール |
|---|---|---|
| `listIds` | 必須 | 並べ替えたあとのリストの ID を、左から順に並べたもの。今あるリストを、ちょうど全部・1回ずつ含める（10件まで） |

- その順番で `position` を 0, 1, 2… と振り直す
- 全部のリストを1つの処理（トランザクション）で書き換えるので、全部成功するか、全部取り消すかのどちらかになる（非機能要件「まとめて保存」）
- リストの中のカードは変えない

**返す内容（204 No Content）**：中身はない（画面はすでに並べ替えて表示しているため）

**エラー**

| 状態 | ステータス | 画面の動き |
|---|---|---|
| `listIds` がない・11件以上 | 400 Bad Request | 元の並びに戻して M-08 |
| `listIds` が今あるリストとちょうど同じでない（足りない・多い・同じ ID が2回・知らない ID） | 409 Conflict | 元の並びに戻して M-08 |

- URL の `/api/lists/order` は、A-09・A-10 の `/api/lists/{id}` と形が似ているが、メソッドが PUT なのでぶつからない

## 4. 開発用のテストデータ

- dev プロファイルで起動すると、リストが1件もないときだけ、テストデータ（リスト3つ・カード6枚）を入れる
- 起動：`./gradlew bootRun --args='--spring.profiles.active=dev'`（`backend` フォルダで実行）
- テストデータの SQL：`backend/src/main/resources/db/testdata/afterMigrate.sql`

### 初期リスト（F-02）との関係

- dev プロファイルなしで起動したときも、リストが1件もなければ、サーバーが「未着手」「進行中」「完了（完了用）」の3つのリストを作る（カードは作らない）
- 処理：`backend/src/main/java/com/example/taskmanagement/startup/InitialListsCreator.java`（サーバーの起動が終わったときに動く）
- dev プロファイルでは、先にテストデータが入るので、初期リストは作らない
